# 蔷薇前端 BaraFrontend

->**为 SillyTavern 的表格数据库提供一套统一的角色面板**<-

->`BaraFrontend-1.0a-hotfix-RosaCaninae`<-

---

把散在十几张表里的属性、技能、特性、状态、资源、关系和人设小传，收进一个常驻在聊天下方的面板；顺带把检定、变更审核和角色卡一起做了。

# 开始之前

## 前置：酒馆助手

**必须先装酒馆助手（JS-Slash-Runner）。** 它是 SillyTavern 的一个扩展，本教程里的两个「脚本」都是跑在它上面的 —— 没有它，脚本连导入的地方都没有。

<https://github.com/n0vi028/JS-Slash-Runner>

安装方式见该仓库说明（SillyTavern → 扩展 → 安装扩展，填入仓库地址）。装好后侧栏会多出「酒馆助手」一项，本教程 Step 1 就从那里开始。

## 然后是这三样

| | 说明 |
| --- | --- |
| **数据库本体** | 表格数据的存储与填写由它负责。蔷薇前端只是它的显示层 |
| **蔷薇前端** | 本项目，一个酒馆助手脚本 |
| **表格模板** | 本项目配套的 `数据库模板-BaraFrontend-1.0-RosaCaninae.json` |

!!! warning
    没有数据库本体，蔷薇前端**能打开但是空的** —— 它自己不存任何表格数据。

数据库本体下载：<https://discord.com/channels/1134557553011998840/1429151492362862683>

# Step 1 · 安装两个脚本

打开**酒馆助手 → 脚本**，点「导入」。

![导入脚本](https://files.catbox.moe/11o3o9.png)

选择**全局脚本库**（这样换角色卡也不用重装），确认。

![选择创建目标](https://files.catbox.moe/inozl6.png)

把「数据库本体」和「蔷薇前端」两个 JSON 都导进来，然后**确认两者都是开启状态**。

![两个脚本都已启用](https://files.catbox.moe/eygkdv.png)

!!! note
    顺序无所谓，但两个都要开。只开前端会得到一个空面板。

# Step 2 · 启用 SQL 模式并配置模板

## 2.1 打开数据库设置

点左下角的**魔杖图标 → SP·数据库**。

![打开数据库](https://files.catbox.moe/kiuiuw.png)

## 2.2 切到高级设置

面板顶部有「基础设置 / 高级设置」两个页签，切到**高级设置**。

![切到高级设置](https://files.catbox.moe/5rfhwh.png)

## 2.3 存储模式选 SQLite

往下拉到**存储模式**，从「原生 JSON」切到 **SQLite**。

![存储模式选 SQLite](https://files.catbox.moe/7em2q7.png)

!!! danger "这一步是必须的"
    蔷薇前端的多表关联（角色卡把十余张表按角色聚合）依赖 SQLite 模式。
    留在原生 JSON 模式下，面板能开，但角色卡里大部分分区会是空的。

!!! note
    切换存储模式会**重置填表提示词**。如果之后填表出现异常，可以切回原生模式对照检查。

## 2.4 导入表格模板

在**表格模板预设**一栏导入 `数据库模板-BaraFrontend-1.0-RosaCaninae.json`。

![表格模板预设](https://files.catbox.moe/yzrsze.png)

导入后确认「当前聊天」一行显示的是这份模板。

!!! warning "认代号，不认小版本"
    模板与脚本靠代号（`RosaCaninae`）配套，两者的小版本号会各自演进 ——
    脚本打了热修（如 `1.0a-hotfix`）而模板仍是 `1.0`，属于正常情况，不必重新导入模板。
    代号不同才需要一起换：那意味着数据结构变了，前端会读不到某些列，
    表现为角色卡的某个分区一直是空的。

# Step 3 · 界面速览

启用后界面**常驻在聊天区最下方**，不需要任何按钮去「打开」它。

```
┌─ 标题栏 ───────── 齿轮  折叠 ┐   ← 设置 / 展开收起
│                             │
│        当前页内容            │   ← 仪表盘 / 某张表 / 审核 / 设置
│                             │
├─ 表格坞 ────────────────────┤
│ 仪表盘  变更审核  变量        │
│ NPC表 3  技能表 11  物品表 4 │   ← 点任意条目切换
└─────────────────────────────┘
```

**表格坞**列出模板里的所有表，右侧数字是行数。点条目即切换，并自动展开内容区。

坞右上角两个小按钮：切换**等宽网格 / 流式排列**，以及**显示 / 隐藏图标**。

!!! note
    嫌坞太长？设置 →「表格坞管理」里可以把用不到的表隐藏，随时能恢复。

## 三种表格视图

每张表右上角可切换：

- **卡片** —— 一行一张卡，宽表在窄屏下的主力形态
- **列表** —— 传统网格，宽屏下横向比较用
- **日历** —— **仅对带日期列的表出现**（小日历表、小日记表）

小日历表与小日记表**只提供日历视图** —— 按日排布的内容拆成卡片反而更难读。

!!! note "日历里的「剧情当前」"
    日历的跳转按钮跳到的是**剧情里的今天**，不是现实日期。
    它优先取小日历表中「与今天的关系 = 今天」的那一行。

# Step 4 · 标记重要角色

新出场的角色会先进 **NPC 表**。想让某个角色获得完整的角色卡（属性、技能、人设小传、关系……），需要把他**晋升**到追踪角色表。

做法：打开 **NPC 表**，找到那个角色，把**归档状态**点成 **待晋升**。

![把归档状态设为待晋升](https://files.catbox.moe/f1g9ew.png)

!!! info "接下来会发生什么"
    前端只负责打这个标记。**下一轮对话时**，AI 读到标记后会把该角色的完整信息
    写入追踪角色表，并从 NPC 表移除原行。所以标记完不会立刻生效，要等一轮。

四个归档状态的含义：

| 状态 | 含义 |
| --- | --- |
| 普通角色 | 默认，留在 NPC 表 |
| **待晋升** | 下一轮迁入追踪角色表，获得完整角色卡 |
| 退场角色 | 已离开剧情，不再跟踪 |
| 删除角色 | 下一轮删除该行 |

!!! warning "默认只有这一列能改"
    表格里那些看起来能点的选项，默认**只有 NPC 表的归档状态**可以改。
    其余的（天气、状态、在场……）是 AI 依剧情写的，玩家点了既无效、
    下一轮还会被覆盖。想全部放开的话，见后面的 **QASmoke**。

# Step 5 · 角色卡

仪表盘里每个重要角色都有一张简易卡，点**「角色卡」**打开完整窗口。

四个页签：

| 页签 | 内容 |
| --- | --- |
| **总览** | 基础属性 / 特有属性（点击即发起检定）、资源条、技能 |
| **库存** | 装备、物品，按类型分组 |
| **特性** | 主动 / 被动能力，增益 / 减益状态 |
| **传记** | 生理与心理合并的连续阅读页、关系、大事记、亲密经历 |

传记页有两个约定：

- **「近期变化」置顶且带橙色标记** —— 它是唯一会随剧情变动的部分，
  与静态设定混在一起会分不清哪些是「当下」、哪些是「设定」
- **成人向分区默认折叠**，展开状态会被记住

## 默认资源

每个主要角色建档时会有四条资源：

| 资源 | 上限 | 恢复 |
| --- | --- | --- |
| 生命值 | 体质 | 长休 |
| 耐力值 | (体质+力量)/2 | 短休 |
| 饱腹度 | 100 | 会话 |
| 性欲值 | 100 | 场景 |

生命与耐力的上限**引用属性**，所以会自动随规则族的量纲走，不需要换算。

要加别的资源（魔法值、气、狂暴次数、意志点……），在**角色资源表**里照格式新增一行即可，模板的说明里给了七条示例。

# Step 6 · 检定

## 从属性发起

在角色卡的**总览**页，直接点任意属性格。弹窗里选难度 → 掷骰 → 结果会连同元叙事文本一起给出。

**掷骰不会自动发送。** 你可以「填入输入框」再编辑，或直接「发送」。

!!! note
    元叙事原文在弹窗里可见 —— 它会原样进聊天记录，你有权先看一眼。

## 从检定建议发起

仪表盘顶部的**检定建议**是 AI 每轮给出的六个行动选项：三条主角、两条角色、一条推进。

点击即**掷骰 + 发送**。骰子命令写在建议表里，前端会自动执行：

```
检定 <角色> <属性> [难度=困难] [奖惩=奖励1]
对抗 <甲> <属性> vs <乙> <属性>
必成 / 必败 / 无
```

发出去的是两段：你的行动描述 + 判定结果的元叙事。

!!! info "不想直接发？"
    每条建议右边有个铅笔按钮，只填入输入框不发送。
    也可以在设置 →「面板与交互」里把默认行为整个改成「填入输入框」。

!!! note
    命令写坏、找不到角色或属性时，会**降级为只发行动文本**并提示原因，
    不会卡住。对抗检定目前只能解析、尚未执行。

# Step 7 · 三种规则族

设置 →「游戏模式与规则」可切换：

| | 判定方式 | 属性量纲 |
| --- | --- | --- |
| **SRD 5.2.1** | d20 + 调整值 ≥ 难度值 | 基础 3–20；特有属性直接记**加值** |
| **BRP SRD 1.0** | d100 ≤ 目标值 | 均为 0–100 的百分比 |
| **说书人** | 掷「属性+技能」颗 d10 数成功 | 均为 0–5 点 |

d20 模式下，属性值旁会多显示一个推算出的调整值（`24` `+7`）。**模板里只存属性值本身**，调整值由前端算，不需要你填两份。

## 切换后要做的事

切完规则族，点「同步属性量纲到模板」→ 预览 → 确认写入。这会把新规则的取值范围与示例写进模板，供 AI 参照。

!!! warning
    切换规则族后，**已有存档的属性值仍是旧量纲**，由 AI 在后续剧情中自行收敛。
    想要一致的数值，建议新开聊天。

    写入只影响**当前聊天的模板副本**，不动全局模板。

# Step 8 · 变更审核

坞里的**变更审核**能看出 AI 每轮改了什么。

用法：先点「建立基线」，之后每轮回来看，列出的就是基线之后的全部改动 —— 新增、删除、逐字段的修改前后值。核对完点「确认并更新基线」，基线前移。

!!! note
    基线**只在你点确认时才前移**。自动跟随当前数据的话就永远比不出东西了。
    切换聊天后旧基线自动失效，不会拿上一个聊天的数据来比。

# 设置面板

点标题栏右上角的**齿轮按钮**。

| 分组 | 内容 |
| --- | --- |
| **外观样式** | 12 套主题 × 深浅两版、界面语言、字号 |
| **布局与浏览** | 坞布局、内容区高度、每页行数、宽度校正 |
| **游戏模式与规则** | 规则族切换、属性量纲同步 |
| **面板与交互** | 点击建议后的行为、QASmoke |
| **表格坞管理** | 显示 / 隐藏坞内条目 |
| **关于** | 版本、许可证、致谢 |
| **高级设置** | 环境自检、恢复默认 |

主题选择是**带色块预览的网格**，每张卡用它自己主题的色值渲染，且预览的是当前深浅设置下**将要生效的那一版**。

## QASmoke

两挡：

- **默认** —— 只有 NPC 表的归档状态可改
- **调试模式** —— 放开全部枚举列，用于校验模板约束

平时用默认就好。

# 排障

## 面板没出现

1. 确认**酒馆助手扩展**本身是启用的 —— 扩展被禁用时，脚本列表里的开关看着还是开的，但不会执行
2. 确认脚本是**开启**状态（Step 1 那张图）
3. 浏览器控制台执行 `BaraFrontend.diagnose()`，会返回 Vue / jQuery / 数据库插件 / SQL 就绪 / 挂载状态

## 面板出现了但表格是空的

- 数据库本体没启用，或没导入表格模板
- 存储模式还停在「原生 JSON」（回到 Step 2.3）
- 设置 →「高级设置」→ 环境自检，看哪一项是 ✕

## 角色卡某个分区一直空着

那张表本来就没有该角色的行 —— 多数是还没到 AI 写入的时候。
如果确定有数据却读不出来，多半是**模板与前端版本不一致**。

## 主题切了但没变化

主题写在酒馆变量里，切换聊天后会重新读取。如果整个面板都没反应，先看控制台有没有报错。

# 近期更新日志

## 26w32

**1.0a-hotfix** 修复了面板一直卡在「数据库未就绪」、刷新几次才偶尔正常的问题。

成因是启动竞态：数据库本体要轮询十几秒才能就绪，而前端只在启动时读一次表格，
抢先跑完就再也不看第二眼 —— 既读不到数据，也订阅不上更新通知。
现在改为退避重试约 37 秒，数据库晚到也能自愈。

本次只动前端的启动时序，数据结构未变，**模板不需要重新导入**。

**1.0** 首个正式版本。
